# 产品与系统架构

更新日期：2026-08-01

## 1. 当前数据边界

“吉拾开张直播排班与妆造协同系统”现以 PostgreSQL 程序数据库作为唯一业务主数据源。主播直播场次、人员日班次、月工时、化妆师可用性、妆造预约、冲突和风险都只读取程序数据。

```text
程序内人工排班 / 智能月排班草案
                ↓ 校验与发布
人员日班次 / 正式直播场次 / 化妆师可用时段
                ↓
推荐 → 并发锁定 → 预约状态机 → 风险与审计
                ↓
主播 / 化妆师 / 场控 / 主管 / 管理员工作台
                ↓
站内实时事件 + 通知 Outbox → 可选飞书机器人群消息
```

飞书多维表格不再是排班或预约的数据源：

- 表格映射、全量同步、增量同步和预约写回均已关闭；
- 历史 `FEISHU` 镜像记录保留用于审计，不显示、不计工时、不占时段、不参与冲突；
- 当前有效来源限定为 `LOCAL`、`LOCAL_OVERRIDE` 和 `AUTO_PLAN`；
- 飞书机器人消息是独立通知渠道，不依赖多维表格。

## 2. 运行组件

- `apps/web`：Next.js 16、React 19、TypeScript，桌面左侧导航与移动端底部导航。
- `apps/api`：NestJS 11，认证、权限、排班、预约、风险、SSE 和通知队列。
- PostgreSQL 16：正式业务数据、时间排斥约束、Outbox 和审计。
- Redis 7：预约短锁，降低并发争抢。
- MinIO：附件对象存储运行环境。
- 本地认证：系统账号、scrypt 密码摘要、签名会话和失败锁定。
- 飞书机器人：可选群通知，不参与业务数据计算。

本地访问地址为 `http://localhost:8088`，API 为 `http://localhost:3002/api`。

## 3. 角色工作台

- 主播：只查询本人直播场次和预约。
- 化妆师：查看本人班次、当前状态和任务，可开始、完成、报异常。
- 场控：按授权直播间查询排班、妆造进度和风险。
- 达人/编导：只查看公开化妆师状态并预约本人妆造。
- 直播主管：跨直播间排班、风险和负载总览。
- 管理员/开发者：维护人员权限、班次、规则、通知和审计。

导航只负责体验；访问控制由 API 守卫、角色和资源数据范围共同执行。

## 4. 排班与预约主链路

1. 排班员在程序中新增人员班次或直播场次，或生成智能月排班草案。
2. 草案按主播连续直播、跨日休息、月工时、房间能力和人员状态生成。
3. 主管逐时段调整、重新校验后发布为 `AUTO_PLAN` 正式场次。
4. 推荐服务按在岗、休息、请假、临时状态、冲突和开播缓冲筛选化妆师。
5. 快速预约在 Redis 锁和 PostgreSQL 事务内二次校验。
6. 预约、状态日志、站内通知和可选飞书群消息 Outbox 在本地事务中创建。
7. 开始、完成和异常由统一状态机校验，并通过 SSE 更新相关页面。
8. 风险引擎检测未预约、临近开播未完成、任务超时和本地排班变化。

## 5. 智能月排班

- 状态为 `DRAFT → VALIDATED → PUBLISHED`，未发布草案不会改变正式排班。
- `PRESERVE_EXISTING` 保留已有本地正式排班；`REPLACE_AUTO_PLAN` 只替换目标月未来的旧 `AUTO_PLAN`。
- `LOCAL` 与 `LOCAL_OVERRIDE` 永远不会被智能发布流程覆盖。
- 发布在一个事务内锁定资源、重新校验、检查有效妆造预约、软取消旧自动排班并写入新场次。
- 每月 20 日 10:00 可自动生成下个月草案，但不会自动校验或发布。
- 未录入人员日班次不再继承飞书或阻断主播草案；显式录入的休息、请假、不可排或解析失败仍会阻断对应时段。

## 6. 可靠性边界

- 所有时间按 `Asia/Shanghai` 展示，数据库保存完整时间点。
- 冲突使用半开区间 `[start, end)`。
- 预约使用幂等键、Redis 短锁、数据库事务、advisory lock 和 GiST 排斥约束。
- 群消息失败只留在通知 Outbox，不回滚本地排班或预约。
- 程序可在飞书完全不可用时继续排班、预约和执行任务。
- 真实飞书机器人群消息仍需配置目标并由群成员完成送达验收。
